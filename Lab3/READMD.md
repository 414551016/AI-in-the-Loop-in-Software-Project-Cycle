#### 一、建立團隊 GitHub 儲存庫與審查流程
  |要做什麼	|為什麼做|
  |--|--|
  |建立 Public 團隊儲存庫，加入 README	|建立全組共用的專題與版本紀錄|
  |邀請組員加入並給予 Write 權限；每人各自 clone	|讓每位成員都能實際參與開發|
  |加入 .github/PULL_REQUEST_TEMPLATE.md	|每次提出修改時，交代改了什麼、重要決策及理由|
  |建立 DECISIONS.md，第一筆記錄初任 code steward 是誰及原因	|保留重要決策的背景，方便日後理解|
  |保護 main：要求透過 PR 合併，至少 1 人核准	|讓修改先經過他人審查，再進入主要版本|
  |每位組員各做一次練習 PR；全組至少完成一次審查與合併，請 TA 確認	|確認大家真正會使用合作流程|

PR（Pull Request）就是「提出修改、請同伴審查，再合併」；code steward 是協助把關修改品質的成員。
設定順序要依網站：先加入 PR 範本與 DECISIONS.md，再開啟分支保護。 網站特別修正了投影片中的順序，以避免初始化時卡在核准要求。直接推送 main 來測試拒絕，網站列為有時間再做的選項；分支保護設定與練習 PR 仍須確認完成。
